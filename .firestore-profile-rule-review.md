# Firestore profile-rule review

Target: `(default)` Firestore Standard edition in `asia-southeast1`.

Profile writes target `users/{uid}`. Registration creates `username`, `email`,
`displayName`, and `createdAt`; profile edits can change `displayName`,
`photoURL`, and `updatedAt`. The profile avatar flow now also writes the
boolean `hasCustomAvatar` to distinguish a user-uploaded avatar from legacy
photos. Older Auth-only accounts are bootstrapped with their Auth email,
display name, and server timestamps when their user document does not exist.

The rules continue to require an authenticated document owner for reads and
writes. Updates allow only the existing profile fields plus `hasCustomAvatar`;
the new field is type-checked as a boolean. Attempts to change another user's
document, add arbitrary fields, alter immutable registration fields, use an
email other than their Auth email during bootstrap, or write a non-boolean flag
remain denied.
